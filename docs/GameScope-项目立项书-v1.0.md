# 项目立项书：GameScope — 独立游戏开发者数据分析助手

> **文档性质**：立项书 / 执行交接文档
> **目标读者**：负责实现的 AI（或开发者）
> **版本**：v1.0（2026-10-29）
> **文档目的**：本文档已锁定所有产品级决策。执行方不得重开「已锁定决策」章节中的任何一项；「允许执行方决定」章节中的事项可自行选择并说明理由。

## 1. 一句话定位

**面向独立游戏开发者的 Web 数据分析工具：接入 Steam 数据后，用自然语言提问即可获得可信的指标分析，每个结论附带口径说明与教学卡片，让不懂商业数据分析的开发者也能看懂自己的游戏生意。**

## 2. 背景与机会（为什么做）

1. **市场空档**：2026 年通用 BI / ChatBI 已是红海（Power BI Copilot、Tableau Pulse、FineBI 等），但 NL2SQL 类产品准确率仅 70–85%，且全部依赖用户自己定义业务口径——独立游戏开发者恰恰没有能力定义「愿望单转化率怎么算才对」。
2. **垂直口径是护城河**：把 Steam 发行领域的指标口径（转化率、退款率、Boxleiter 估算等业内经验值）固化进产品，是巨头不会逐行业做深、小团队能做扎实的部分。
3. **目标用户真实痛点**：绝大多数独立开发者只看得到 Steamworks 后台的原始数字，看不懂「愿望单转化 8% 是好是坏」「退款率 16% 意味着什么」，更不会做归因分析。
4. **差异化双轮**：垂直口径沉淀（可信度）+ 教学卡片（教育属性）。错误的分析比没有分析更糟，因此「口径透明 + 校验」是产品生命线，不是附加功能。

## 3. 目标用户

| 维度 | 描述 |
|------|------|
| 身份 | 独立/小团队游戏开发者（1–5 人），已上架或即将上架 Steam 游戏 |
| 能力 | 会看数字但不懂商业数据分析；不会 SQL；不想学 BI 工具 |
| 场景 | 发行前后复盘流量转化、愿望单健康度、发售首周表现、折扣策略效果 |
| 排除 | 3A 发行商数据分析团队（需多游戏数据库）；纯玩家（无 Steamworks 权限） |

## 4. 已锁定决策（执行方不得重开）

| # | 决策 | 结论 | 依据 |
|---|------|------|------|
| D1 | 垂直领域 | 独立游戏 / Steam | 创始人即目标用户（dogfooding）；数据源明确；竞争少 |
| D2 | 产品形态 | Web 应用（浏览器访问） | 免安装、迭代快、LLM Key 留在服务端 |

| D4 | 信任机制 | 每个分析结果必须展示：指标定义、计算口径、参与计算的行数/时间范围 | 防幻觉是产品生命线 |
| D5 | MVP 数据范围 | 单游戏、单用户；不做多游戏对比数据库、不做竞品监测 | 控制 MVP 范围 |
| D6 | 视觉方案 | 极简纯形状+颜色设计（无插画、无复杂视觉资产），图表用成熟开源库 | 创始人无美术资源 |
| D7 | 教学定位 | 每个指标配「教学卡片」：是什么 / 为什么这么算 / 健康区间 / 下一步该问什么 | 教育属性是核心差异化，不是附加 |

## 5. 数据源规格（MVP 必须支持，M1 至少前两项）

| 数据源 | 获取方式 | 提供字段 | 优先级 |
|--------|----------|----------|--------|
| Steamworks 后台 CSV（流量与转化） | 用户手动导出上传 | 页面曝光、访问、购买、流量来源、地区 | P0 |
| Steamworks 后台 CSV（愿望单） | 用户手动导出上传 | 愿望单增删、时序 | P0 |
| Steam Web API（公开） | 输入 App ID 自动拉取 | 评论（ISteamReviews）、价格、折扣（appdetails） | P1 |
| CCU 峰值/在线曲线 | 第三方公开数据（如 SteamCharts 类页面），须遵守目标站点 robots 与限速 | 历史在线人数 | P2（可砍） |

**合规红线**：只用官方 API 与用户自愿上传的数据；任何抓取必须限速（≥3 秒/请求）并尊重 robots.txt；不得存储用户 Steam 账号密码，OAuth（若有）只做只读授权。

## 6. 指标模板库（核心资产，MVP 需 12–15 个）

每个模板包含五要素：**定义 / 计算口径（精确到字段与公式）/ 健康区间（标注为业内经验值）/ 推荐图表 / 教学卡片文案**。

首批模板清单（口径为初稿，执行方需在实现时为每条标注「经验值，非官方标准」）：

**发售前（愿望单健康）**
1. 愿望单积累速率（周净增；区分自然增长/活动脉冲）
2. 愿望单删单率（删单/(删单+新增)，经验预警线 >8% 需关注）
3. 愿望单/页面访问转化（加购意愿，经验区间 3–10%）

**发售期（首周表现）**
4. 愿望单→首周销量转化（经验区间 10–20%；<5% 常见于愿望单灌水或发售准备不足）
5. 首周销量占比（首周/首月，用于判断长尾型 vs 脉冲型）
6. 页面转化率（访问→购买，经验区间 5–12%）
7. 退款率（<10% 正常；>15% 警示，常与性能问题/预期不符相关）

**长线运营**
8. 折扣愿望单脉冲系数（折扣期愿望单增速/平日常态值，经验 5–20 倍）
9. 评论销量估算（Boxleiter 数：评论数 × 25–70，区间跨度大，必须展示为区间并注明是粗估）
10. 好评率分档（>95% 压倒性好评 / >80% 特别好评 / >70% 多半好评）
11. 流量来源结构（Steam 商店内搜索/外部/愿望单页，诊断曝光瓶颈）
12. 地区销售结构（定价与本地化决策依据）

## 7. MVP 功能清单与验收标准

### F1 数据接入
- 上传 Steamworks 导出的 CSV（两种），自动识别文件类型并解析入数据库。
- 输入 App ID 拉取公开评论与价格数据。
- **验收**：创始人提供的真实 CSV（或按 Steamworks 导出格式构造的测试 CSV）解析成功率 100%；错误文件给出可读的报错（指出是哪一列、哪一行）。

### F2 指标看板
- 首页展示已计算好的 12–15 个模板指标：数值 + 推荐图表 + 健康区间标注（在区间内/外用颜色区分，遵循中国习惯：达标用绿、警示用红——本产品非股票场景，红=警示）。
- **验收**：无 LLM 参与时，纯模板计算全部正确（以手工计算样例为基准的单元测试覆盖每个模板）。

### F3 AI 问数（核心功能）
- 用户自然语言提问（如「最近三个月愿望单为什么跌了」），系统执行：意图识别 → 定位涉及的字段/模板 → 生成计算（走结构化中间表示，**不直接生成 SQL**，参考 NL→语义层→查询 的分层思路）→ 返回图表 + 结论。
- **必须展示**：所用口径、参与计算的行数、时间范围、以及「这个结论的置信度说明」（如数据量过少时提示「样本不足，仅供参考」）。
- **验收**：准备 30 条标准测试问题（含 10 条数据不足以回答的陷阱问题），≥24 条（80%）回答正确或正确拒绝；陷阱问题不得编造答案。

### F4 教学卡片
- 每个指标与每类分析结论附带教学卡片（是什么/为什么这么算/健康区间/下一步该问什么，每张 ≤120 字）。
- **验收**：全部 12–15 个模板指标卡片齐全，文案经创始人审核。

### F5 校验层（sanity check，防错分析）
- 每次计算前自动检查：行数是否异常、时间范围是否完整、空值占比；异常时在结果中显著提示。
- **验收**：注入脏数据（重复行、缺日期）时，系统给出警告而非静默输出错误数值。

### F6 账号与项目
- 邮箱注册/登录；每个账号可创建 1 个「游戏项目」（多项目留给 v2）。
- **验收**：基础认证流程可用，数据按账号隔离。

## 8. 明确不做（MVP 范围外）

- 多游戏对比数据库 / 竞品监测 / 行业基准数据集（v2 方向）
- 拖拽式仪表盘编辑器、自定义指标建模
- 移动端适配（响应式可用即可，不做原生）
- 团队协作 / 多租户
- 预测建模（时序预测等，v2+）
- 微信小程序（Web 先行验证）

## 9. 技术指引（允许执行方调整，需说明理由）

| 层 | 建议方案 | 备注 |
|----|----------|------|
| 前端 | Next.js (React) + Tailwind + ECharts 或 Chart.js | SSR 利于 SEO（内容营销获客） |
| 后端 | Next.js API Routes 或独立 Node/Python 服务 | 单人维护优先简单 |
| 数据库 | PostgreSQL（起步可用 SQLite） | CSV 时序数据量小 |
| LLM | 任一主流 API（Claude / GPT / GLM），**必须封装为可切换** | 成本与可用性风险对冲 |
| 部署 | Vercel / 国内轻量云（目标用户主要在国内开发者社区） | LLM 调用延迟 P95 < 15s |

**LLM 使用纪律**（写入执行方的实现约束）：
1. 结构化输出（JSON schema 约束），模板计算在代码中执行，LLM 只负责意图理解与结论文案——**禁止 LLM 直接算数**。
2. 每次问数展示完整口径链路。
3. Token 成本预算：单次问数 < 5K tokens 输入；对话上下文做摘要压缩。

## 10. 里程碑

| 阶段 | 周期 | 交付物 | 通过标准 |
|------|------|--------|----------|
| M0 骨架 | 1 周 | 项目脚手架 + CSV 解析器 + 3 个指标模板端到端跑通 | 创始人用真实/测试 CSV 操作成功 |

| M2 内测 | +2 周 | 5–10 名真实独立开发者试用 | 至少 3 人完成「上传数据→问 3 个问题→看懂结论」全流程 |

## 11. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| LLM 编造分析结论 | 高 | F3/F5 双层防线：代码算数 + 口径展示 + sanity check；陷阱测试集常驻回归 |
| Steam 页面结构变更导致解析失败 | 中 | 优先官方 API；页面解析模块独立、可热修 |
| 冷启动：用户没有 Steamworks 数据 | 中 | 提供「演示数据集」（一款模拟独立游戏的全周期数据）用于首次体验 |
| LLM API 成本失控 | 中 | 可切换 Provider + 用量上限告警 + 上下文压缩 |
| 单人维护不可持续 | 低 | MVP 功能克制；技术栈选主流方案降低交接成本 |

## 12. 商业化方向（MVP 不实现，仅约束设计不堵死）

- 个人版免费（1 个项目）+ Pro 订阅（多项目、历史对比、周报推送）；
- 行业模板包与深度教学内容作为增值项；
- 禁止在 MVP 中埋点任何付费墙逻辑。
