## 2. 必须修（blocking，1 条）

### B1 愿望单图「愿望单总量」折线序列没有数据，图例空挂

- **位置**：`src/components/charts/WeeklyNetChart.tsx:45-54`（第二个 series 只有 `name: "愿望单总量"`（行 46），**缺 `data` 属性**）；对照 `src/lib/metrics/wishlistAccumulation.ts:91,100`（`WeekBar.totalEnd` 被计算与赋值，但全库 grep 仅有类型定义、初始化、赋值三处，**无任何消费方**）。
- **问题**：图例声明了「愿望单总量」（WeeklyNetChart.tsx:17），组件注释宣称「周净增柱状 + 愿望单总量趋势线」（行 7），但该序列 data 为空，ECharts 不渲染任何点或线。
- **影响**：愿望单积累速率卡片图上出现一个没有对应图形的图例项，tooltip 亦无该序列；演示时创始人会看到「图例说有、图上没有」的断点，与交付物「端到端演示」的自述不符。
- **依据**：series 定义逐行核对；`totalEnd` 全库检索确认无消费。
- **修复方向**：series[1] 补 `data: weeks.map(w => w.totalEnd)` 即可（totalEnd 语义即周内最后一个非空总量）。

## 3. 值得考虑（建议，可留 M1，6 条）

1. **教学卡片「健康区间」要素未全部带「非官方标准」全称**：`src/lib/metrics/wishlistAccumulation.ts:72,151`、`src/lib/metrics/pageConversion.ts:37` 仅写「（经验值）」；仅 `refundRate.ts:38` 完整。附录 A 要求「每处使用都必须附带此免责说明」。同卡 rangeNote（wishlistAccumulation.ts:59,133；pageConversion.ts:50,64,109；refundRate.ts:51,65,125）与页脚全局声明（`src/app/page.tsx:115`）均有全称，故不阻断，建议 M1 统一文案。
2. **F5 空值检查覆盖不全**：`src/lib/sanity/check.ts:63` 只对愿望单「新增」列做空值占比检查；流量 CSV 的访问/购买为空时按 0 参与计算（`src/lib/csv/traffic.ts:61-62`）且无任何警告——空访问会虚高转化率。建议补 traffic 空值占比检查（「防错分析」是立项书第 2 节的产品生命线，宜在 M1 接真实数据前补齐）。
3. **报错行号可能与物理行号漂移**：`src/lib/csv/parse.ts:31` 的 rowNo 按「过滤空行后的序号 +1」编号（空行在行 24-27 被过滤）。当前 dirty fixtures 无空行、演示不受影响；真实导出若中间含空行，「第 N 行」会指错行。
4. **一行多列坏值只报第一处**：`src/lib/csv/wishlist.ts`（numCell 结果 `cells.find` 取首个失败项）——用户需反复上传才能发现同行的其余坏列。建议一次收集全部坏列。
5. **P0 流量报告的「地区」维度未解析**：`src/lib/csv/specs.ts` TRAFFIC_SPECS 无 region 字段，真实导出含地区列时该列被静默忽略。M0 三个模板不依赖地区，不算违规；M1 模板 12（地区销售结构）落地时须同时扩展解析与存储结构。
6. **重复代码**：`src/lib/csv/index.ts:182`（aggregateDaily）与 `src/lib/metrics/index.ts:40`（aggregateTrafficDaily）为同逻辑的按日聚合，建议合并为一处。
