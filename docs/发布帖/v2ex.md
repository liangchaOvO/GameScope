# 发布帖备稿 · V2EX

> 节点建议：/go/create 或 /go/nodejs（技术向），标题带「AGPL」「本地优先」「BYOK」

---

**GameScope**：给独立游戏开发者用的 Steam 数据分析工具，AGPL-3.0 开源，本地优先。

起因：Steamworks 后台只有原始数字，通用 BI 又太重。这个工具把独立发行圈的经验口径固化成 12 个指标模板（愿望单积累、删单率、页面转化 5–12%、退款率 >15% 警示、Boxleiter 估算、折扣脉冲系数、地区结构……），每个结果强制展示完整口径链路（公式 + 参与行数 + 时间范围），并附教学卡片。

技术栈：Next.js 15 (App Router) + SQLite（better-sqlite3）+ ECharts + Tailwind。几个自认为值得讨论的设计：

1. **LLM 不算数**：AI 问数只让模型输出意图 JSON（指标 + 时间范围），过白名单校验后由本地模板代码计算——模型没有产出数字的通道；解析失败降级到看板。30 条标准问题（含 10 条陷阱）随仓库做回归；
2. **两种模式**：本地模式（默认）免登录单用户、数据存本机 SQLite、零遥测；在线试用模式匿名自动会话 + 会话级存储 TTL 自动清理 + 用户 Key 仅内存单次转发（不落盘不写日志）+ IP 限速 + 匿名功能计数（仅次数，无内容）；
3. **BYOK**：任意 OpenAI 兼容端点——智谱 / DeepSeek / Kimi / scnet.cn 免费额度 / 本机 Ollama 零成本；不配 Key 看板全功能可用；
4. CSV 解析是别名表驱动的（Steamworks 列头变体只改一行别名）。

仓库（AGPL-3.0）：<你的仓库地址>，`npm install && npm run dev` 或 Docker。内置虚构游戏演示数据，30 秒走完「上传 → 问 3 问 → 看懂结论」。

求拍砖的重点：指标口径本身是否站得住（尤其折扣脉冲系数的启发式判定）、AGPL 下做在线试用站的合规边界、以及 better-sqlite3 在多平台部署的坑。
