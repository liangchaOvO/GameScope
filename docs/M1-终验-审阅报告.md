## 三、值得考虑（3 条）

1. **「降级分支不携带任何 MetricResult」表述失实**（pipeline.ts:15 注释、tests/ask.test.ts:181 测试标题、演示指南 §4 F3 行同款措辞）。实际 `degrade` 返回 `metrics: MetricResult[]`（pipeline.ts:23、:49＝`computeAllMetrics` 的 12 个代码计算结果）。成立的真实性质是「任何分支都不含**由 LLM 输出派生**的指标结果；LLM 只能白名单路由 metricId/时间/维度」。建议三处统一改写，避免创始人据此误解降级页没有数值。
2. **mock 关键词存在盲区（自构变体实测）**：「愿望单转化成销量怎么样」→ 误路由 `wishlist-accumulation`（合理应为 wishlist-launch-conversion 族；指南 §6 声称该误路由已修，实际仅覆盖含「首周」的 fixture 句式，mock.ts:15-16、:24）；「下个月的愿望会涨吗」类未来时态→ 以历史指标卡作答而非 unknown（未来时态词不在 trapKeywords，mock.ts:28-31）。均不产生编造数值，30 题集与 GLM 路径不受影响；建议扩 mock 词表并纳入回归。
3. **req.json 仍被 git 跟踪**（仓库根，GLM 冒烟测试请求体，内容无凭据）。fe9f502 清理了 cookies1/2、overview.json、demo_result.json 四个调试文件，此文件遗漏，与「调试残留已清理」口径不一致（无安全影响）。建议 `git rm --cached req.json` 并补 .gitignore。
